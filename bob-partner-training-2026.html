Auto-approve 설정

Auto-approve가 켜져 있으면 Bob이 파일을 수정할 때 매번 승인 팝업 없이 진행됩니다. 오늘 실습에서는 켜두는 것을 권장합니다.

⚠️ 주의

운영 환경이나 민감한 저장소에서는 Auto-approve를 사용하지 마세요.

2

/init으로 프로젝트 탐색

bob-practice/를 열고 Bob 채팅창에 /init을 입력하면 작은 연습 프로젝트의 구조 탐색을 시작할 수 있습니다. 생성되는 요약과 파일 배치는 Bob 버전과 폴더 상태에 따라 달라질 수 있습니다.

Bob IDE 채팅 입력
/init

확인 포인트

  • Bob이 README.md와 package.json을 근거로 연습 프로젝트와 npm test 스크립트를 설명했는가
  • 서비스 구조를 단정하지 않고 src/, 테스트 파일, practice-artifacts/를 함께 확인했는가
  • 추가 컨텍스트가 필요하면 이 handout의 흐름에 맞춰 README, package 설정, 소스 파일, 테스트 파일, 연습 아티팩트를 멘션해 다시 확인합니다

선택: Node 검증과 오류 해석

Node.js와 npm이 준비된 참가자는 터미널에서 테스트를 실행해 볼 수 있습니다. 실행 결과는 Bob IDE 채팅에 붙여 넣거나 @terminal로 참조합니다.

Bob IDE 채팅 입력
이 폴더의 package.json을 읽고 프로젝트 구성을 한 줄로 요약해줘.
PowerShell — 선택 검증
cd bob-practice
npm test
Bob IDE 채팅 — @terminal 활용
@terminal
위 실행 결과에서 실패한 항목과 다음 확인 단계를 정리해줘.
⚠️ @terminal 안내

Bob이 Shell integration may not be active.를 표시할 때만 확인합니다. Bob IDE Settings를 열고 Shell Integration을 검색한 뒤 Terminal › Integrated › Shell Integration: Enabled를 켭니다. 또는 settings.json에 "terminal.integrated.shellIntegration.enabled": true를 설정합니다.

설정 후 기존 터미널을 닫고 새 터미널을 열어 다시 @terminal을 시도합니다. 그래도 사용할 수 없다면 터미널 출력을 Bob 채팅에 직접 붙여 넣고 계속 진행하세요. 터미널과 Node 실행은 오늘 실습에서 선택 사항입니다.

테스트 스크립트가 완료되면 Node 검증까지 마친 것입니다. 일부 항목이 실패하거나 실행하지 못해도 IDE 설정이 끝났다면 워크숍을 계속 진행할 수 있습니다.

Custom Mode 만들기

Custom Mode는 .bob/custom_modes.yaml로 정의합니다. 프로젝트 전용 역할 페르소나를 만들 수 있습니다.

.bob/custom_modes.yaml
customModes:
  - slug: practice-reviewer
    name: Practice Reviewer
    roleDefinition: >
      연습 프로젝트 검토자로 README, 소스, practice-artifacts를 읽습니다.
      목적, 담당자/진입점, 불확실한 점을 구분하고
      다음 실습에서 확인할 질문을 표로 정리합니다.
      파일을 직접 수정하지 않고 분석 결과만 제공합니다.
    allowedTools:
      - read
    groups:
      - read

실습

practice-reviewer Mode에서 입력

1

Rules — 출력 형식 제어

Rules 파일에 응답 형식 규칙을 적으면 Bob이 일관된 형식으로 답합니다.

.bob/rules-agent/practice.md 예시
# Practice Rules

## 응답 형식
- 분석 결과는 반드시 표(Markdown table)로 정리한다
- 변경 계획에는 반드시 "변경 파일", "변경 이유", "검증 방법" 열을 포함한다
- 위험 수준은 높음/중간/낮음 세 단계로만 표시한다
- 코드 변경 전에 계획을 먼저 제시하고 승인을 구한다

## 범위 제한
- 한 번의 요청에서 수정 파일은 최대 2개
- 현재 열린 bob-practice 폴더 밖의 파일은 읽거나 수정하지 않는다
- 실제 과제 서비스 이름을 가정하지 않는다

실습: Rules 적용 전후 비교

  1. 위 Rules 없이 Bob에게 "practice-artifacts 세 파일의 목적과 불확실성을 표로 분석해줘"를 요청하고 결과를 확인합니다
  2. 위 Rules를 .bob/rules-agent/ 아래 파일로 저장합니다
  3. 같은 질문을 다시 요청하고 응답 형식 차이를 비교합니다
  4. 비교를 확인한 뒤 .bob/rules-agent/practice.md 임시 파일을 삭제해 이후 실습이 이 규칙을 이어받지 않도록 합니다

MCP — Notion 샌드박스 실습

MCP(Model Context Protocol)는 Bob이 외부 시스템을 도구로 호출할 수 있게 해주는 프로토콜입니다. 이 선택 실습은 현재 열린 bob-practice 프로젝트의 프로젝트 범위 설정으로 진행하며, Bob이 Notion MCP로 별도의 개인 테스트 전용 워크스페이스에 연결해 정해진 범위 안에서 읽기와 작은 쓰기 작업을 확인합니다.

⚠️

이 실습은 본인이 새로 만든 테스트 전용 Notion 워크스페이스에서만 진행합니다. 평소 사용하는 개인 업무 워크스페이스, 회사, 고객사, 운영, 프로덕션, 기밀 콘텐츠가 있는 워크스페이스나 페이지는 절대 사용하지 않습니다. OAuth 승인은 연결 절차일 뿐 서버 접근을 기술적으로 전부 제한하는 안전장치라고 가정하지 않습니다. 안전 경계는 별도 테스트 워크스페이스를 쓰는 운영 규칙으로 만듭니다. 네트워크/OAuth/Node-npm 사용이 어려우면 강사 데모를 관찰하고 의도한 읽기/쓰기 경계만 기록합니다.

1) 개인 테스트 전용 Notion 워크스페이스 만들기

  1. Notion에서 이번 워크숍에만 사용할 새 개인 테스트 워크스페이스를 만듭니다.
  2. 회사, 고객, 운영, 프로덕션, 기밀 자료를 복사하거나 연결하지 않습니다.
  3. 이후 작업은 현재 연결된 테스트 전용 워크스페이스 안에서 새로 만드는 고유 이름 항목만 대상으로 합니다.

2) bob-practice의 Bob MCP 설정에 Notion MCP 구성 추가

  1. Bob 패널에서 MCP 탭을 열고 Use MCP Servers를 켭니다.
  2. Edit Project MCP를 열어 bob-practice/.bob/mcp.json에 아래 내용을 저장합니다. 템플릿은 templates/project-mcp.notion.example.json입니다.
  3. 이 설정은 npx로 로컬 stdio bridge를 시작해 Notion의 hosted MCP(https://mcp.notion.com/mcp)에 연결합니다.
.bob/mcp.json — Notion hosted MCP bridge
{
  "mcpServers": {
    "notion": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.notion.com/mcp"]
    }
  }
}

3) 등록 후 브라우저 authorization 완료

  1. 설정을 저장한 뒤 Bob MCP 탭에서 Notion 서버가 등록되는지 확인합니다.
  2. 첫 도구 사용 또는 연결 확인 과정에서 브라우저가 열리면 본인 계정으로 Notion OAuth authorization을 완료합니다.
  3. 비밀번호, 토큰, OAuth 코드, 세션 정보는 누구와도 공유하지 않고 문서나 채팅에 붙여넣지 않습니다.
  4. 승인 화면에서 테스트 전용 워크스페이스를 선택했는지 다시 확인합니다.

4) Bob IDE 재시작

  1. 브라우저 authorization을 마친 뒤 Bob IDE를 완전히 종료했다가 다시 엽니다.
  2. bob-practice 프로젝트 폴더를 다시 열고 MCP 탭에서 Notion 서버와 도구가 다시 보이는지 확인합니다.
  3. 연결이 준비되지 않으면 무리하게 진행하지 말고 강사 데모를 보며 의도한 읽기/쓰기 경계를 기록합니다.

  4. Settings → Chat → Rollback을 엽니다.

Rules / Skills / Custom Mode 생성

Rules 생성
이 프로젝트에 맞는 Agent용 Rules 파일을 .bob/rules-agent/ 아래에 만들어줘.
포함 내용:
- 응답 언어: 한국어
- 변경은 최대 파일 2개
- 표와 체크리스트 중심으로 출력
- Redis, MySQL, Docker는 제안하지 않음
Custom Mode 생성
.bob/custom_modes.yaml에 security-reviewer 모드를 추가해줘.
이 모드는 코드를 수정하지 않고 보안 위험 분석만 수행하는 읽기 전용 모드야.
Skill 생성
.bob/skills/env-check/SKILL.md를 만들어줘.
이 Skill은 저장소 환경 설정 상태를 근거 파일 기준으로 점검하는 절차야.

C2 — 트러블슈팅

참고 자료
1

환경 문제

Bob IDE가 실행되지 않는 경우

  • Bob IDE를 재시작한 뒤 다시 로그인합니다
  • bob.ibm.com에서 최신 IDE 설치 파일을 확인합니다

npm install 실패

  • 네트워크/프록시 문제 → 회사 VPN 상태 확인
  • Node.js 버전 불일치 → node --version으로 18 이상 확인
  • 에러 로그 전체를 Bob IDE 채팅에 붙여 넣거나 @terminal로 참조해 원인을 물어보세요

포트 충돌

powershell — 포트 사용 확인
netstat -ano | findstr :8080
netstat -ano | findstr :3000
2

Bob 동작 문제

Custom Mode가 드롭다운에 안 보이는 경우

  • .bob/custom_modes.yaml YAML 문법 오류 확인 (들여쓰기 주의)
  • Bob IDE 재시작

Skill이 인식되지 않는 경우

  • 파일 경로 확인: .bob/skills/{name}/SKILL.md
  • frontmatter의 name 필드가 있는지 확인

Bob이 파일을 너무 많이 수정하는 경우

  • .bob/rules/ 또는 현재 Mode의 .bob/rules-{mode-slug}/에 "변경 파일은 최대 2개" 규칙을 추가합니다
  • Plan Mode로 먼저 계획을 승인받은 뒤 Agent Mode로 전환합니다
  • Rollback으로 즉시 되돌릴 수 있습니다 (히스토리 패널)

컨텍스트 창이 가득 찬 경우

  • 새 채팅을 시작합니다
  • @멘션으로 필요한 파일만 지정합니다
  • 분석 범위를 폴더 단위로 좁힙니다

실습 진행 가능 기준

✅

실행이 실패해도 됩니다. Bob IDE로 파일을 읽고, 분석하고, 계획을 세우고, diff를 리뷰하는 것이 오늘의 핵심 학습입니다.

  • Bob이 파일을 읽고 설명할 수 있다 → 실습 가능
  • Bob이 변경 계획을 표로 만들어 준다 → 실습 가능
  • 서비스가 실행되지 않아도 → 실습 가능
  • 테스트가 실패해도 → 실패 이유를 Bob에게 물어보면 됨

C3 — 미션 힌트

막혔을 때 참고
⚠️

먼저 스스로 시도해보고, 정말 막혔을 때 힌트를 확인하세요.

1

M1 힌트

런타임 설정 규칙 찾기

프론트엔드 프레임워크는 브라우저에 노출되는 런타임 설정에 별도 규칙을 둘 수 있습니다. Bob에게 프로젝트 설정, 예시 설정, 실제 호출 코드를 함께 읽고 어떤 규칙이 적용되는지 근거로 설명하게 하세요.

추가 질문
이 프론트엔드가 어떤 빌드 도구를 쓰는지 프로젝트 설정에서 확인하고,
브라우저 코드가 읽을 수 있는 런타임 설정 규칙을 근거와 함께 설명해줘.
2

M3 힌트

응답 계약 비교

정답 형태를 먼저 정하지 말고, 각 엔드포인트가 어떤 JSON 모양을 반환하는지 표로 만들게 하세요. 테스트가 기대하는 모양과 실제 코드가 반환하는 모양이 다르면 그 차이가 수정 후보입니다.

추가 질문
mock-api의 각 GET 엔드포인트에 대해 실제 응답 JSON 모양과 테스트 기대값을 비교표로 만들어줘.
차이가 있으면 어떤 사용자/클라이언트 코드에 영향을 줄지 설명해줘.
3

M5 힌트

누락된 테스트 후보 찾기

핸들러가 분기하는 조건과 테스트가 실제로 호출하는 조건을 나란히 비교하면 빠진 케이스를 찾기 쉽습니다. Bob에게 바로 테스트 코드를 쓰게 하기 전에 후보 목록과 우선순위를 먼저 받으세요.

추가 질문
auth-service의 라우트별 성공/실패 분기와 현재 테스트가 호출하는 경로를 비교표로 만들어줘.
워크숍 시간 안에 추가할 가치가 큰 테스트 후보 2~3개만 우선순위로 추천해줘.
4

M7 힌트

Subagent가 실행되지 않는 경우

  • Bob IDE에서 로그인과 Mode 드롭다운이 정상인지 확인합니다
  • Subagent 기능은 Agent Mode에서만 사용 가능합니다
  • Subagent 대신 "세 파일을 순서대로 분석해줘"로 대체할 수 있습니다
